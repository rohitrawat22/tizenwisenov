1. Executive Summary

This document details the findings of an end-to-end security, runtime stability, and architecture audit conducted on the Wise Player Tizen codebase. The application is an IPTV and Video Streaming client built with Flutter for Samsung Tizen OS (Smart TVs), Android TV, and Web platforms.

During the review, 16 distinct issues were identified across multiple layers:

6
Critical (Crashes / Build Failures)
5
High (Data Leaks / Memory Leaks)
4
Medium (Dead Code / Stale UI)
1
Low (Unused Imports / Deprecations)

The most critical findings include:

  • Build Failure on Tizen: The manifest targets Tizen 6.5, which fails because the native rootstrap iot-headed-6.5-device.core is missing in Tizen Studio, while Runner.csproj targets tizen80.
  • Fatal Runtime Crashes: Invalid string-to-int fallback casting in router.dart, a duplicate assignment to a late final variable in tv_show_subscription_plan.dart, and premature isEmpty invocation on a nullable secret in fetch_phone_info_mac.dart.
  • Security & Privacy Exposure: Hardcoded provider credentials (username & password) inside tv_upload_playlist_screen.dart and upload_playlist.dart that discard user input.
  • Platform Incompatibility: Use of flutter_inappwebview for PayPal checkout, which has no Tizen OS engine implementation and crashes on TVs.
  • Socket & Resource Leaks: Unclosed HttpClient instances in redirect resolution, leading to connection exhaustion on embedded TVs.

3. Detailed Defect Analysis & Fixes

1. Build Failure: Missing Rootstrap 6.5 & TargetFramework Mismatch Critical
tizen/tizen-manifest.xml:5 | tizen/Runner.csproj:5

Root Cause:

The manifest was updated to api-version="6.5" with <profile name="tv"/>, but Tizen Studio on the development machine only has the Tizen 8.0 rootstrap installed (tizen-8.0-device.core). Furthermore, Runner.csproj specifies <TargetFramework>tizen80</TargetFramework>. When flutter-tizen build tpk executes, it tries to compile against iot-headed-6.5-device.core which does not exist, causing the build to fail: 

exception:Error: The rootstrap iot-headed-6.5-device.core could not be found.
To install missing package(s), run:
C:\tizen-studio\package-manager\package-manager-cli.exe install IOT-Headed-6.5-NativeAppDevelopment-CLI

Impact: The application cannot be compiled or packaged into a .tpk for testing or deployment on TV devices.

Resolution: Either revert api-version="8.0" and <profile name="common"/> in tizen-manifest.xml to match the installed Tizen 8.0 SDK, OR install the Tizen 6.5 Native package via Tizen Package Manager.
2. Fatal Type Cast Error: String Fallback assigned to int resumeSecond Critical
lib/core/routes/router.dart:154

Root Cause:

In the router definition for AppRoutes.videoPlayer:

final int resumeSecond = data['resumeSecond'] ?? "";

The fallback value when data['resumeSecond'] is null is the empty string "" instead of 0. Assigning a String to an int variable triggers an immediate runtime exception: TypeError: type 'String' is not a subtype of type 'int'.

Impact: Any navigation to the video player where resumeSecond is null immediately crashes the application.

Resolution: Change line 154 to: 
final int resumeSecond = (data['resumeSecond'] as num?)?.toInt() ?? 0;
3. Fatal Crash: LateInitializationError on _isPhone Critical
lib/presentation/screen_view/common/subscription/tv_show_subscription_plan.dart:71,109

Root Cause:

The state variable is declared as: 

late final bool _isPhone;

And inside didChangeDependencies(): 

_isPhone = isPhoneWidth(context);

In Flutter, didChangeDependencies() is invoked whenever inherited widgets (Theme, MediaQuery, Locale) update. Because the field is declared late final, any second invocation of didChangeDependencies() throws: LateInitializationError: Field '_isPhone' has already been initialized.

Impact: The subscription screen crashes whenever screen dimensions change or keyboard/theme toggles.

Resolution: Remove the final modifier: 
bool _isPhone = false;
4. Crash: Null Pointer on isEmpty in Device Registration Critical
lib/presentation/screen_view/common/auth/fetch_phone_info_mac.dart:393

Root Cause:

Line 393 checks device credentials before registration:

if (data['deviceSecret'].isEmpty || data['deviceSecret'] == null)

In Dart, boolean OR (||) evaluates left-to-right. On a first install when deviceSecret is null, calling .isEmpty on null throws: NoSuchMethodError: The getter 'isEmpty' was called on null.

Impact: First-time device registration can crash before creating an account on the server.

Resolution: Check for null first, or use safe navigation: 
if (data['deviceSecret'] == null || (data['deviceSecret'] as String).isEmpty)
5. Missing Tizen Plugin: flutter_inappwebview on TV Critical
lib/presentation/screen_view/common/subscription/pay_pal_chekout_screen.dart:60

Root Cause:

PayPalCheckoutScreen attempts to instantiate an InAppWebView. flutter_inappwebview does not have a Samsung Tizen platform channel. Calling it on Tizen throws MissingPluginException.

Impact: Paying via PayPal inside the TV app crashes the screen.

Resolution: On TV devices, route exclusively to QrCheckoutTvScreen (which allows mobile phone QR code payment) and disable direct webview checkouts on TV profiles.
6. Crash: Unhandled String / HTML Error Response in Dio Error Handler Critical
lib/presentation/screen_view/bloc/api_services/api_services.dart:174 & dio_client.dart:72

Root Cause:

The error handler expects all error responses from Dio to be JSON Maps:

e.response?.data['message'].toString()

When an upstream streaming server, proxy, or Cloudflare returns an HTML error page (e.g. 502 Bad Gateway or 504 Gateway Timeout), e.response?.data is a String. Indexing ['message'] on a String throws NoSuchMethodError: Class 'String' has no instance method '[]', causing the error handler to crash.

Impact: Unhandled exceptions crash the Bloc layer on server hiccups or offline modes.

Resolution: Safely inspect data type before map indexing: 
final data = e.response?.data;
final msg = (data is Map) ? data['message']?.toString() : null;
errorMessage = msg ?? "Server error occurred";
7. Security & Integrity: Hardcoded Credentials & Discarded Playlist URL High
lib/presentation/screen_view/common/upload_playlist/tv_upload_playlist_screen.dart:96 & upload_playlist.dart:324

Root Cause:

In both upload screens, the submission logic replaces the user's input with a hardcoded IPTV URL containing plain credentials: 

final res = await apiService.hitPostApi(
  reqData: {
    "name": nameCtrl.text.toString(),
    "m3uUrl": "http://line.vpnworld.pro/get.php?username=15F2C2&password=512608&type=m3u_plus&output=mpegts",
  },
  endpoint: "/api/playlist/m3u",
);

Impact: The user's entered playlist URL is ignored, and private IPTV credentials are hardcoded and leaked into version control and device binaries.

Resolution: Pass urlCtrl.text.trim() instead of the hardcoded test URL, and revoke any exposed credentials.
8. Socket & Memory Leak: Unclosed HttpClient in Redirect Resolution High
lib/presentation/screen_view/bloc/repo/api_repo.dart:193

Root Cause:

Inside _resolveRedirect(), an instance of HttpClient() is allocated on every redirection loop, but client.close(force: true) is never called.

Impact: On Tizen Smart TVs with strict OS-level socket limits, rapidly switching channels leaks sockets until reaching socket exhaustion (SocketException: OS Error: Too many open files), causing video playback to fail completely until the app restarts.

Resolution: Wrap client usage in a try / finally block: 
final client = HttpClient()..connectionTimeout = const Duration(seconds: 6);
try {
  final request = await client.getUrl(uri);
  ...
} finally {
  client.close(force: true);
}
9. Race Condition: Delayed 2-Second Timer Wipes Active Stream State High
lib/presentation/screen_view/bloc/wise_bloc.dart:430-441

Root Cause:

When a stream opens, ResetVideoUrlEvent is dispatched. The bloc handler waits for a 2-second delay and then wipes the state: 

_resetVideoUrlEvent(ResetVideoUrlEvent event, Emitter<WiseState> emit) async {
  await Future.delayed(const Duration(seconds: 2), () async {
    emit(state.copyWith(videoUrl: '', isVideoLoaded: false, selectedVideo: VideosOnPerticulerChannelModel.empty()));
  });
}

Impact: If a user navigates between channels quickly, this delayed timer executes while the new stream is loading and destroys the new stream's URL and channel metadata.

Resolution: Remove the delayed state wipe. Reset state deterministically when leaving the player screen or navigating to a new video.
10. HTTP Protocol Violation: GET Request with Body in hitPostApiCureent High
lib/presentation/screen_view/bloc/api_services/dio_client.dart:43-52

Root Cause:

The function named hitPostApiCureent (note typo in Current) accepts reqData, but executes dio.get(endpoint, data: reqData). Sending a payload body with HTTP GET violates RFC 7231 and is rejected or stripped by standard web servers, proxies, and CDNs.

Resolution: Change dio.get to dio.post.
11. Token Refresh Race Condition during Concurrent 401 Responses High
lib/presentation/screen_view/bloc/api_services/dio_client.dart:163-176

Root Cause:

When a session token expires, multiple parallel requests (e.g. initial playlist categories, user status, pinned playlists) simultaneously trigger 401 errors. onError spawns multiple independent _refreshToken() calls concurrently without a mutex or request queue.

Impact: The server invalidates the refresh token on the first exchange, causing subsequent refresh attempts to fail and prematurely logging the user out.

Resolution: Implement a single in-flight Future<String?> lock for refresh token operations.
12. Broken Feature: Download Invoice PDF Discards Downloaded File Medium
lib/presentation/screen_view/bloc/repo/api_repo.dart:449

Root Cause:

In downloadInvoicePdf(), the PDF binary is retrieved via HTTP GET bytes, but saving the file is commented out: 

//await _savePdf(res.data, invoiceId);

Impact: Clicking "Download Invoice" consumes bandwidth and API resources, but does not save or display any invoice to the user.

Resolution: Re-enable saving to application storage or opening with open_filex / platform file viewer.
13. UI Bug: TV Home Screen Stuck on "Fetching location…" Medium
lib/presentation/screen_view/common/auth/wise_player_tv_home_screen.dart:80,777

Root Cause:

lib/location.dart is completely commented out, and the location lookup call in wise_player_tv_home_screen.dart is disabled. However, the UI continues to render _locationText, which never updates from its default state: String _locationText = 'Fetching location…';

Impact: The user sees a permanent loading label on their TV screen.

Resolution: Set a clean default (e.g., app name or date/time banner) or re-enable the IP-based geolocation fallback.
14, 15 & 16. Dependency & Platform Support Issues Medium
lib/core/utils/get_device_info.dart | lib/core/routes/router.dart

Summary of Items:

  • 14. Undeclared Dependency: package:uuid is directly imported in get_device_info.dart:11, but is not listed in pubspec.yaml. Any change in transitive dependencies will break the build.
  • 15. Hard Desktop Crash: currentOperatingSystem() throws UnsupportedError('Unsupported platform: windows'), preventing developers from testing on Windows or desktop.
  • 16. Missing Symbol: router.dart:24 imports SimpleVideoScreen via show, but SimpleVideoScreen does not exist in tv.video.dart.
Resolution: Add uuid: ^4.5.1 to pubspec.yaml, provide a desktop fallback in get_device_info.dart, and remove the nonexistent symbol from router.dart.
